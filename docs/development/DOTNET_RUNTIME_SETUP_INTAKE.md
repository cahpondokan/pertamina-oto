# .NET runtime acquisition for Windows Setup

1 October 2026. Agent0 technical intake for the user's explicit request to download/install missing .NET10 Runtime x64 inside the OTO wizard. This is scoped development verification, not Production or blanket dependency approval. Existing compiler and Windows Framework libraries are reused; no new NuGet/build-tool dependency is acquired.

Provenance/license sources reviewed before binary acquisition: Microsoft's Windows installation documentation https://learn.microsoft.com/en-us/dotnet/core/install/windows and the version-pinned runtime source license https://github.com/dotnet/runtime/blob/v10.0.12/LICENSE.TXT (MIT; retain license/third-party notices in Microsoft's unmodified package). OTO does not repackage/embed the runtime, modify its terms, or act as its signing publisher. The installer shows a Microsoft license link and explicit prerequisite-install action. Vendor executable licensing remains applicable. Full product distribution/signing/legal approval remains separate.

Security admission for this scoped test: download to a private development artifact/quarantine folder only; do not execute/install it on this development PC. Verify exact metadata SHA512 and full Windows Authenticode chain/revocation plus signer organization Microsoft Corporation. Failure is blocking; never bypass certificate/TLS validation. Runtime URL is HTTPS, pinned in compiled source, without redirects, mirrors, scripts, telemetry or document identifiers. Download is bounded to128MiB and10minutes, cancelable. A runtime update requires a new reviewed source pin/build. This evidence is not a claim that all future versions or all vulnerabilities are cleared.

User-facing flow: ordinary wizard is asInvoker and .NET Framework4.8-based (available with supported Windows10 build19041+ / Windows11). Only Microsoft's verified installer requests runas/UAC with `/install /passive /norestart`. It remains locked against replacement until the process exits. Exit0/3010 requires a fresh runtime detection before OTO installation; failures/UAC cancellation stop. OTO installation remains per-user. No forced reboot or app closure. Existing modern .NET10 runtime takes an entirely local path without runtime download.

Remaining external acceptance: real clean-Windows missing-runtime, UAC allow/deny, standard-user elevation, interrupted/reboot scenarios and Windows edition/support matrix. No clean-VM installation claim is made by simulated coordinator tests. The OTO EXE is an unsigned development candidate; Authenticode signing authority and public activation remain separate gates.
