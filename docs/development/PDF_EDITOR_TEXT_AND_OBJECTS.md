# Edit PDF — original text and object interaction

Date: 21 September 2026. Scope: current user request, local development only; no phase/release approval implied. Baseline HEAD `84cbb0f`, existing dirty worktree retained. No subagents, packages, PDFium integration, upload, or production mutation.

## Delivered behavior

- Added objects have eight resize handles with 20px hit targets and small visible grips. Corners preserve image proportions; Shift constrains other corner resizes. Pen points scale with their bounding box.
- Pointer move, Delete, Ctrl+D, 1pt arrow movement, Shift+arrow 10pt movement, Esc deselect, undo/redo. Typing in text/number/selection controls does not delete/move the document object. Canvas keyboard focus fixed after a failing audit; not waived.
- Original-text mode highlights supported source runs and provides a matching accessible dropdown. Enter or Apply replaces the source string; Delete removes a selected run; Restore returns to source text.
- Replacement modifies the existing `Tj` operand, not a white overlay or appended replacement. Font/position are retained. TrueType WinAnsi and CIDFontType2 Identity-H with explicit supported ToUnicode maps are admitted by the managed implementation.
- Replacement characters must already be demonstrably used in the same page/font. Only basic Latin single-character mappings are admitted. Replacement width must not exceed the original run; unsupported glyphs, stale IDs, duplicate edits, complex text states and unsupported encodings are rejected without publication.
- Real preview generated by the existing isolated worker, then loaded by Windows PDF rendering. Preview files are uniquely named, held only while needed, and cleaned on replacement/close. Undo/redo is transactional: history is committed only after successful preview generation.
- Save uses a unique new filename, original read locks, existing staging and cancellation. No source overwrite.

## Remaining limitations / not claimed

This is not full parity with Acrobat or another general PDF editor. Text within TJ kerning arrays, form XObjects, tagged text, arbitrary font encodings, shaping/non-Latin characters, longer paragraph reflow, changing original font/style/size, and OCR editing remain unsupported. Existing document restrictions (forms/signatures/encryption, rotated/cropped/nonstandard page coordinates) remain. Deleting text is not a certified sensitive-data redaction feature.

Physical pointer drag/pinch, full keyboard traversal/screen reader and network-denial tests remain manual acceptance work. Automated resize math and keyboard-handler tests are not represented as physical input simulation. No full UI/UX or production sign-off is claimed.
