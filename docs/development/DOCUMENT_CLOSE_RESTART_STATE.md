## Verified cause

The pre-fix binary in `before/` runs the real `CloseDocumentsAsync` and native ContentDialog. A synthetic Watermark source plus custom output is guarded; cancelling close preserves the draft. After accepting the original discard button, the audit still reports `Pengaturan hasil:Watermark` and fails the empty-screen pending assertion (exit 1). Evidence: `before/document-close-audit/audit.txt`, `before-build.txt`.

Close removed `toolDrafts`/checkpoints/files but retained shared options/output values. `RestartPendingWork` read those controls when the current route named the tool, even on its empty intake screen. `SaveToolDraft` could capture the detached values again during navigation. A related empty-tool route could capture another tool's controls. A session ending therefore needed an explicit lifecycle boundary and actual control ownership, rather than treating a missing file as proof of completion.

## Implemented contract

- `Tutup dokumen` ends only the targeted tool/editor/read session. Tool/editor pending work gets save/process-and-save, `Tutup tanpa menyimpan`, and `Kembali mengedit`; the safe default retains work. Button text wraps instead of clipping in compact dialogs. Labels, tooltip and accessibility names identify the action. Verified pristine/saved sessions can close directly.
- Save from close must produce a new existing output and a clean successful checkpoint. Failure, cancellation or an unsupported/no-input save retains the session. A previous successful output cannot masquerade as a newly completed save.
- Ended tool IDs and shared-control ownership prevent empty/history routes from recapturing or restoring an ended draft. Fresh input starts a new session with default controls. Only the ending tool's draft/checkpoint/credential and specialised source/selection/undo/rotation/preview state are released. Other tool/editor drafts remain.
- `Keluarkan dari daftar` removes an input, never a filesystem file. Merge, generic source and JPG controls share the same remove contract. Removed-input compositions stay guarded, including the last input; an explicit close is required to end them. Organizer retains provenance and Undo until close, and exposes explicit close on its empty-composition screen.
- Reader close releases only its own document/search/render ownership. Pending or queued stale opens cannot reattach it. History/menu auto-open is suppressed until another explicit open. If other drafts remain, a visible landing message and review action explain them. Compact reader windows expose labelled close/review through `Pilihan dokumen`.
- Editor close protects original/added inline typing and selection while the dialog owns focus. Cancel does not implicitly commit original text. Drawing, shape and drag remain guarded; unfinished gestures cannot use the save action. Approved discard clears gesture/inline/undo/result association and releases locks. Close refuses release during active async opening/rendering/processing; existing render validity checks remain.
- Credentials remain separate memory-only session state, never serialized with drafts/history/logs/evidence. Failed/cancelled saves retain them; successful saves or approved close release only the corresponding session. Password-only work stays guarded across tools and can be reviewed.
- Pending restart rows identify source filenames, tool and a reason. The existing busy refusal and fresh pending-state revalidation immediately before restart commit remain. No force-close, bulk discard, updater security change or restart-guard bypass.
