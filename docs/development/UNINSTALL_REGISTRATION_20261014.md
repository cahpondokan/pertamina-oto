The user reported that OTO was missing from the uninstallable-app list. The actual Windows account had an installed current build `20261014-002535-877d8390` (product 0.3.0), but no HKCU uninstall entry. The installer previously copied binaries and created a Desktop shortcut without registering an uninstaller. Windows uninstall metadata fields are documented by [Microsoft](https://learn.microsoft.com/en-us/windows/win32/msi/uninstall-registry-key); this implementation uses the current user's HKCU registration, not MSI or machine-wide installation.

## Scope and implementation

- `eng/WindowsUninstall/Program.cs`, `Tests.cs`, and `eng/Build-Uninstaller.ps1`: standalone .NET Framework 4.8 helper using the existing compiler and Windows libraries. No new dependency or system runtime installation. Registration copies the helper/config into the stable installation and sets a visible PERTAMINA OTO entry, product version, icon, installation location and quoted uninstall command.
- Uninstall is interactive, defaults to cancellation, targets only the fixed per-user `Programs/PertaminaOTO` installation, and rejects traversal, reparse points, invalid identity, busy app processes and update/setup/file locks. It never force-closes an application. Known version and launcher/helper directories are application-owned; unknown root files and directories are retained. Documents, settings and history outside the installation are not deletion targets.
- Cleanup enumerates and validates the deletion plan first, removes individual files and then empty directories, and retains a bounded recovery journal for interrupted cleanup. No recursive shell deletion, elevated uninstall, silent removal, or Windows `.pdf` UserChoice change. Only matching OTO shortcuts/associations are removed. A staged helper copy remains in its unique temporary directory; it is small and is deliberately not removed by a shell cleanup job.
- `eng/Build-DownloadPackage.ps1`: packages the verified helper and exact size/hash inventory. `eng/WebDistributionInstaller/{InstallPackage,Program}.cs`: verifies that inventory before activation, registers after successful installation, and refuses installation over pending uninstall. `eng/WindowsSetup/{SetupFlow,SetupTests}.cs`: distinct failure message if application installation succeeds but uninstall registration fails. Existing legacy package validation remains supported.
- The default legacy development-only `Install-LocalDesktop.ps1` and in-app update mechanism are unchanged. The current user's existing installation was repaired directly; other existing installations need this repair or a newly packaged full installer. DisplayVersion reflects the most recent registration/full installation, and is not refreshed by an older in-app updater.
