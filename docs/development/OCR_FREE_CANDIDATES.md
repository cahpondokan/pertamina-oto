## Bukti RapidOCR dan batasnya

[RapidOcrNet](https://github.com/BobLd/RapidOcrNet) menyediakan koordinat baris/kata/karakter, progress pengenalan, dan cancellation. Dokumentasi menyatakan dukungan .NET 8/10 dan pipeline lokal. Klaim ini belum diuji di PERTAMINA OTO. Library ini implementasi C# pihak ketiga dari RapidOCR; jangan menyamakannya dengan paket Python resmi atau menganggap status pemeliharaan keduanya identik.

[Metadata NuGet 4.2.0](https://www.nuget.org/packages/RapidOcrNet) menunjukkan publikasi 9 September 2026 dan dependensi minimum: Clipper2 2.0.0, Microsoft.ML.OnnxRuntime serta Managed 1.29.0, SkiaSharp serta NativeAssets.Linux.NoDependencies 3.119.1. Ini minimum upstream, **bukan lock yang disetujui**. Paket yang diterima nanti harus dipin seluruh graph-nya; native assets Windows, Linux yang tidak diperlukan, Microsoft runtime, Skia notices dan transitive assemblies harus diinventarisasi. OpenCV/Python tidak diperlukan untuk jalur C# ini.

Empat file kandidat awal: ch_PP-OCRv5_mobile_det.onnx, ch_PP-LCNet_x0_25_textline_ori_cls_mobile.onnx, latin_PP-OCRv5_rec_mobile_infer.onnx, ppocrv5_latin_dict.txt. Hindari v6/GPU pada evaluasi pertama agar scope dan resource terbatas. [PaddleOCR daftar bahasa](https://github.com/PaddlePaddle/PaddleOCR/blob/main/docs/version3.x/algorithm/PP-OCRv5/PP-OCRv5_multi_languages.md) menyebut Indonesian/id dan English/en. Ini dukungan upstream, bukan bukti akurasi model konversi terpilih; model dan dictionary harus cocok. Jangan menampilkan pilihan ID/EN/both sebagai engine berbeda bila backend memakai satu model Latin yang sama.

[RapidOCR README](https://github.com/RapidAI/RapidOCR/blob/main/README.md) menyatakan gratis, open-source, offline dan Apache-2.0. Hasil pencarian menampilkan uraian model dan MODEL_LICENSES.md, tetapi kedua lokasi MODEL_LICENSES.md yang dicoba mengembalikan 404, dan halaman README yang berhasil dibuka tidak memuat manifest tersebut. Maka lisensi/attribution/provenance **empat model exact belum diverifikasi**; jangan menutup gate lisensi hanya berdasarkan snippet pencarian atau label paket. Cocokkan model upstream resmi, konversi, SHA-256 dan pemberitahuan redistribusi saat intake.

[ONNX Runtime LICENSE](https://github.com/microsoft/onnxruntime/blob/main/LICENSE) MIT. [Release resmi 1.30.0](https://github.com/microsoft/onnxruntime/releases/tag/v1.30.0) memuat hardening model loading, external-data path, bounds/shape/memory. Maka calon runtime yang dievaluasi adalah 1.30.0 CPU, bukan menerima minimum 1.29.0 otomatis. Kompatibilitas API dan graph model dengan RapidOcrNet 4.2.0 tetap perlu dibuktikan. [Advisory page ORT](https://github.com/microsoft/onnxruntime/security/advisories) tidak menampilkan advisories publik; ini bukan bukti tidak ada kerentanan. Advisory Python `onnx` converter tidak otomatis berlaku pada ORT C# inference: inventarisasi komponen aktual dan reachability diperlukan.

[Dokumentasi ORT](https://onnxruntime.ai/docs/) menyarankan inspeksi model dan lingkungan aman untuk sumber tidak dipercaya. [C# DisableTelemetryEvents API](https://github.com/microsoft/onnxruntime/blob/main/csharp/src/Microsoft.ML.OnnxRuntime/OrtEnv.shared.cs) tersedia, tetapi [isu initialization telemetry](https://github.com/microsoft/onnxruntime/issues/25573) berarti pemanggilan API saja belum membuktikan zero-egress sejak startup. Terapkan kontrol jaringan OS dan verifikasi egress sebelum klaim LOCAL; model hanya path lokal yang terikat hash, tanpa unduhan runtime, external data tidak terkendali atau custom operators/models pengguna. Worker process dengan batas memory/time dan penghentian process tree masih diperlukan; CancellationToken bukan sandbox.

## Windows OCR dan Tesseract

[Microsoft Windows.Media.Ocr](https://learn.microsoft.com/en-us/uwp/api/windows.media.ocr?view=winrt-26100) mensyaratkan package identity untuk desktop. Enumerasi AvailableRecognizerLanguages dan TryCreateFromLanguage diperlukan untuk capability nyata. Folder OS yang sebelumnya terlihat en-US/en-GB/ar-SA tidak membuktikan engine dapat dijalankan, dan bahasa Indonesia belum terbukti. Tidak tepat mengubah seluruh packaging aplikasi semata agar menghindari admission OCR tanpa persetujuan desain.

[Tesseract release terbaru](https://github.com/tesseract-ocr/tesseract/releases/latest) masih 5.5.3 saat riset. Delapan patch upstream membentuk rangkaian hingga revision 552771236b0d80cbdb0c7dd856120fa21a4672e5; [contoh commit akhir](https://github.com/tesseract-ocr/tesseract/commit/552771236b0d80cbdb0c7dd856120fa21a4672e5). Penelitian sebelumnya membandingkan 5.5.3 ke revision ini: 54 commits/84 changed files dan seluruh delapan patch ada. Revision tersebut development snapshot, VERSION masih 5.5.3, bukan stable 5.5.4. Delapan commits unsigned menurut API; Signed-off-by tidak sama dengan tanda tangan kriptografis. Metadata advisories sebagian belum konsisten dengan patch. Tidak boleh menganggap delapan temuan telah ditutup sebelum review keseluruhan snapshot, regression dan security disposition. Backport delapan patches juga menghasilkan fork privat yang perlu controlled change. Lihat OCR_SOURCE_INTAKE.md untuk delapan advisory dan temuan installer sebelumnya.

## Integrasi nyata yang diperlukan

Pemeriksaan lokal: Desktop.App.csproj menargetkan net10.0-windows10.0.19041.0 dan WindowsPackageType=None. Worker saat ini mengacu PDFsharp dan tiga paket Microsoft pendukung, belum OCR. PdfJpgExport.cs dan ReaderContinuousScroll.cs sudah menggunakan Windows.Data.Pdf rendering; itu dapat menjadi dasar raster input setelah desain worker diverifikasi, bukan bukti rendering dapat langsung dipindahkan ke worker tanpa perubahan.

OCR library menghasilkan pengenalan gambar, bukan seluruh fitur PDF. Integrasi masih harus: render halaman secara serial dengan batas pixel/tile; pertahankan sumber/gambar/page size A3/A2; skip text-bearing pages/regions tanpa menduplikasi teks pada PDF mixed; ubah polygon pixel ke PDF point dengan rotation/crop/padding/resize yang benar; embed invisible text/font Unicode; simpan nama unik lalu reopen/search/validate; reader offer dan progress/cancel; kontrak recognition bersama. Default cap 1024 pixels upstream berisiko melewatkan huruf kecil pada A2/A3: benchmark tiling dan fidelity wajib, jangan menurunkan gambar PDF asli untuk mempercepat OCR.

## Langkah berikutnya dan authority

1. Usulkan **acquisition-only RapidOcrNet 4.2.0**, source revision terkait paket, empat model Latin/dictionary di atas, serta paket CPU ORT 1.30.0/Managed dan dependency graph exact yang direview. Tahap ini mencatat metadata terlebih dahulu; hash belum tersedia bukan alasan mengarang hash atau menerima versi wildcard. Setiap tambahan/upgrade native dependency harus melalui admission tersendiri. Tidak ada auto-install, build, runtime atau modifikasi aplikasi dalam tahap ini.
2. Static intake: verifikasi feed/signature/hash/source mapping, safe extraction, SBOM lisensi/notices/model conversion, advisory disposition setiap component/version dan output paket Windows. Jika bukti model tidak cukup, intake HOLD.
3. Setelah admission dan authority execution terpisah: uji sintetis offline ID/EN/mixed, word alignment dan search, A3/A2/memory/timeout/cancel/temp/source hash; verifikasi telemetry/zero-egress dengan kontrol OS. Gunakan satu worker CPU serial; jangan menjalankan dokumen sensitif untuk pembuktian awal.
4. Integrasi produk lokal baru setelah test/capability terbukti; tidak ada phase promotion, production approval atau physical UAT dari laporan ini.

Kesimpulan: tersedia kandidat gratis yang realistis. **RapidOcrNet menjadi pilihan utama untuk evaluasi terkontrol; belum ada kandidat yang sudah admitted dan siap dipakai di aplikasi ini.** Jalur ini menghindari perubahan packaging Windows dan private Tesseract fork sebagai langkah pertama, tetapi tidak menghapus kewajiban keamanan/model/dependency admission.
